# 緊急脆弱性をオフラインで照合する

固定カタログの照合対象と未確認の範囲を調べるときに読むガイドです。

組込みの`runtime-advisories`は、PHP・Node.js・Next.js・NGINX・GitLab・Apache Tomcatの版宣言を照合します。
出典付きカタログは、2026-10-22に公式の配布元情報と照合しました。

## 検査しないもの

- ファイルは実行しません。imageの取得、依存解決、脆弱性情報サービスへの接続も行いません。
- 動的タグ、別名依存、プレリリース、未対応系列、曖昧な宣言は未確認です。
- 配布元の修正と実稼働環境は未確認です。
- OpenSSLの実リンク先とBeyondTrustのpatch状態は、この静的照合の対象外です。
- 不一致は安全性の判定ではありません。

## 対応する宣言を読む

対応する安定完全版とimage variantだけを比較します。

| 追跡済みの入力 | 読み取る宣言 |
|---|---|
| `.nvmrc`、`.node-version`、`.php-version`、`.tool-versions` | ランタイムの版宣言 |
| Dockerfile | 単純な公式imageの`FROM`宣言 |
| npm lockfile v1〜3 | Next.jsの解決版 |

## 照合結果を読む

指摘が0件の場合も、宣言ごとに各アドバイザリーの照合結果を残します。

| 照合結果 | 意味 |
|---|---|
| 一致 | 宣言した版がカタログの項目に一致し、修正版を報告します。 |
| 記録した範囲での不一致 | 記録された範囲内では宣言した版が一致しません。 |
| 未確認 | 記録されたカタログでは宣言を評価できません。 |

全計画の必須検査であり、範囲は常に部分的か非対応です。
省略しても`PASS`にはなりません。
計画と結果にカタログのhashと確認日を固定します。
カタログを変えたら新しい計画が必要です。

> Q. 検査中にカタログを更新しますか。
>
> A. 更新しません。更新は検査の外で、出典の確認と回帰試験を経て行います。

## 同じ版のschemaを使う

| 契約 | schema |
|---|---|
| 計画 | `scanmux.plan/v2` |
| レポート | `scanmux.report/v2` |
| Web | `scanmux.web/v2` |

これは基本の契約です。任意のTrivyを使う場合のv3計画・レポートは、Trivyのガイドを参照してください。
保存済みv1 JSONは変更しません。旧計画は実行できません。
PC/Sitesの版が合わないクライアントから変更操作は開始できません。
この組込み検査の設定はschema 1のままです。
`runtime-advisories`の実行ファイル指定は受け付けません。
