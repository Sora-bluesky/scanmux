# ローカルWeb画面を使う

ブラウザーで公開GitHubリポジトリを取得し、範囲の確認、検査、結果の保存を行うためのガイドです。

## 対応するリポジトリ

画面は`https://github.com/owner/repository`を受け付け、現在のHEADを取得します。
ほかのhost、非公開リポジトリ、任意ref、資格情報やクエリ付きURLは未対応です。
ブラウザーからツールや設定ファイルのパスは変更できません。

## ローカルセッションを開始する

信頼するコントローラー設定でサーバーを起動します。

```sh
node bin/scanmux.mjs serve --config /absolute/controller.json
```

コマンドが一度だけ表示する、非公開のセッションURLを開きます。
サーバーは`127.0.0.1`の空きポートだけで待ち受けます。
URLのfragmentはセッション用の資格情報です。
画面はそれをセッションストレージへ移し、アドレスバーから除去します。

端末は起動したまま使います。Ctrl+Cで中断を要求し、処理が落ち着いた後にサーバーを閉じます。
ブラウザーを再読み込みすると、同じサーバープロセスの現在のジョブへ再接続します。
サーバーを再起動すると新しいセッションになり、以前のジョブは引き継ぎません。

## リポジトリを取得して範囲を確認する

公開GitHub URLを入力し、**取得して範囲を確認**を押すと現在のHEADを取得します。
信頼するGitを使い、認証、checkout、hooks、redirect、submoduleは使いません。
固定commit、除外、依存ファイルを確認してから、検査を明示的に開始します。
同時に動くジョブは1つです。
同じ計画の実行要求を繰り返しても二重起動しません。

## ジョブを中断する

取得中の中断は次工程を禁止し、現在のGitコマンドが自然に終了するまで待ちます。
既存の準備期限は維持します。
検査中は既存のプロセスツリー中断処理を使います。
終了と出力検査が落ち着くまでは、画面に中断待ちを表示します。

> Q. 中断後に新しいジョブを開始できないのはなぜですか。
>
> A. 終了を確認できなければ、実行枠を保持します。取得ソースの複製は削除し、削除に失敗した場合だけ残します。対象プロセスの終了を確認するまでは、データの削除や再起動をしないでください。

## 結果を保存する

JSONダウンロードは、非公開の実行ディレクトリへ保存した、秘密検査済みのbytesを返します。
完了または中断の終了確認後に、取得オブジェクトとsnapshotを削除します。
レポートはOSの一時ディレクトリ内の`scanmux-*`へ、現在の利用者だけがアクセスできる形で残します。

別の計画へ進む前に、必要な結果をダウンロードしてください。
ダウンロード開始の表示は、ブラウザーの保存完了を意味しません。

> Q. サーバーやOSの異常終了後に、ソースやジョブ履歴は復旧されますか。
>
> A. 異常終了では一時ディレクトリにソースが残る場合があります。自動回収と永続的なジョブ履歴はありません。

## 所有者限定のSitesを使う

許可するOriginを1つ指定し、ローカル画面の**Sitesで開く**から接続します。

```sh
node bin/scanmux.mjs serve --config /absolute/controller.json --site-origin https://your-site.example
```

Sitesへ配信するのは静的な画面だけです。
Git取得、検査、結果は同じPCで扱います。
PCと元のローカル画面を開いたまま使ってください。

> Q. ブラウザーにローカル接続を拒否されたり、APIの版が合わなかったりする場合はどうしますか。
>
> A. ローカル画面を使ってください。

D1/R2や外部AI APIは不要です。
Sites自体の無料利用を保証するものではありません。

## 安全性

- セッションURLは非公開で扱い、共有ログへ載せないでください。
- ローカル画面はセッション用の資格情報をセッションストレージへ移します。
- Sites用トークンはURLやブラウザー保存領域へ保存しません。
- 保存したレポートは非公開で扱います。
- 対象プロセスの終了を確認するまでは、保持したソースの削除や再実行をしないでください。
